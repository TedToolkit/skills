# Problem-driven curriculum guidance

Read this reference when the user wants principles, judgment, repeatable procedures, or a
recurring case taught through practice.

Map each selected idea to the first real change or failure that makes it useful. Keep the sequence
problem-driven: show the existing approach, the new pressure, a verifiable improvement, and the cost
or case where the named solution is unnecessary. Do not create a catalog chapter merely to cover
names. Keep terminology consistent across the outline and visual assets. A catalog may inform
candidate coverage, but schedule a lesson only when its example and prerequisites make the use
credible within the episode duration.

When a recurring case ties the course together, keep its domain knowledge within the audience's
stated prerequisites and introduce every case rule before using it to justify a technical choice.
Use small examples for mechanisms, chapter snapshots for an evolving case, and isolated comparisons
for alternatives when one continually expanding project would obscure the lesson.
Do not force a named method into the main example solely for coverage.
